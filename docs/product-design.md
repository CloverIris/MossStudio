# 产品设计

## 1. 定位

MossStudio 是面向 MOSS-Image 的桌面创作工作台。目标是把提示词、布局、模型、生成和 Agent 放进一个连续工作流，而不是让用户在启动器、浏览器表单和终端之间切换。

不是：

- 官方 Gradio 的皮肤
- 多 Case 多引擎终端
- 训练器前端
- 模型/算法仓库

## 2. 双窗口

| 窗口 | 职责 |
| --- | --- |
| MossStudio | 创作页 + 顶部页面导航（引擎/模型/设备/训练/画廊/诊断/设置）+ 终端抽屉 |
| Kohaku Trainer | 独立训练工作台；保留 Python/Git 环境 |

没有启动器窗口、设备管理器窗口、终端窗口或每个 Case 一个窗口。

## 3. 创作页

### 3.1 信息架构

按"输入 → 发送"分层，而不是按组件分区：

```
┌ 项目条 ─────────────────────────────────────────────────────────┐
│ [项目 tabs]                              [后端就绪] [保存] [新建] │
├ 画布条 ─────────────────────────────────────────────────────────┤
│ [选择|画框|手型] [物体|人物|文字] ⋯   Canvas 1 · 1024×1024 · 2 区域  [− 100% + ⤢] │
├───────────────┬─────────────────────────────────┬───────────────┤
│ 左栏：写什么   │                                 │ 右栏：有什么   │
│ 提示词        │        画布板（自由拖拽）        │ 图层           │
│ 布局描述      │        布局 / 结果 Canvas        │ Agent          │
│ 生成参数      │                                 │ 图像解析       │
│ 图库          │                                 │               │
├───────────────┤                                 │               │
│ ● 布局 Prompt │                                 │               │
│ [开始生成]    │                                 │               │
└───────────────┴─────────────────────────────────┴───────────────┘
```

设计约束：

- **左栏只回答"这次要生成什么"**：提示词、布局描述、采样参数、图库，底部固定动作条把「将发送什么」和「开始生成」放在一起。
- **右栏只回答"画布上有什么"**：图层列表 + 辅助工具（Agent、图像解析）。不再承载布局描述。
- 左右栏可拖动调宽、可收起为边轨；收起后保留输入状态。

### 3.2 布局 Prompt 的合成

原本需要「编译 → 插入到 Prompt → 再生成」三步，现在合并为一件事：

| Canvas 状态 | 发送内容 | 左栏提示 |
| --- | --- | --- |
| 有可见区域 | 由 `summary` + 区域编译出的布局 JSON | `● 布局 Prompt · N 个区域` |
| 没有区域 | 左栏手写提示词 | `● 手写提示词` |

「预览」随时可看完整 JSON；`插入到 Prompt` 仍保留为高级用法（把编译结果写进手写框）。

### 3.3 画布板

- 卡片位置持久化在 `x/y`，可自由拖动；拖动标题栏移动卡片，空白处拖动平移整块板。
- 卡片按自身宽高比呈现，`512²` 占 `1024²` 四分之一面积。
- 滚轮以光标为锚点缩放；点选卡片居中到 125% 工作缩放；`⤢` 适配全部卡片；右下角缩略图导航。
- 生成中卡片有呼吸光晕与底部进度绑带，生成结束自动恢复；不再弹出终端窗口。
- 结果永远是**新的一张结果 Canvas**，放在来源卡片下方，重跑不会覆盖历史。

### 3.4 Project tabs 与工程

- 顶部 tabs 管理多个 Project：双击重命名、hover 删除、拖动排序。
- 修改后 tab 出现未保存圆点，`Ctrl/Cmd + S` 显式保存；同时保留 1.2s 自动保存。
- 新建 Project 自动编号，避免多个「未命名 Project」。

### 3.5 图层

- 图层顺序 = 布局 Prompt 里的区域编号，可拖拽排序。
- 画布与列表双向定位；支持隐藏、锁定、不透明度、区域提示词。

## 4. 引擎

- 一个 engine 一个 `moss-server` 进程，一个 FIFO。
- 本机与 Linux SSH host 走同一协议。
- 任务不绑定 Instance；模型、设备、引擎分开选择。
- 默认 system-cuda 包；缺 cuBLASLt 时提示 bundled（+700MB）或 system + 原生 NVIDIA wheel。

## 5. 模型与 Project

- 模型是组件化 bundle：dit / text encoder / vae / support。
- Project 保存的是**一组 Canvas**（布局与结果），不是单张画布快照。
- 多张画布在画布板上平铺；不再用 tabs 表达画布。

## 6. 设置

按任务域分 8 个分区，左侧导航、右侧只渲染当前分区：

外观与交互 / 存储与画廊 / 网络与下载 / 通知与更新 / 局域网访问 / 设备 / 训练与外部工具 / 诊断与关于。

Python、PyTorch、pip 归入「训练与外部工具」，并明确标注 **MossInfer 推理不需要 Python**。

## 7. Agent 与 GBC

- Agent 是可停靠面板，不是独立窗口；写入 Prompt 前必须确认。
- GBC 是外部可选工具；图像解析导入画布，不参与启动。缺少 GBC 不影响创作。

## 8. 非目标

- 不做多个推理引擎实例并行跑同一类 Case。
- 不把官方 MOSS 仓库 clone 进推理链路。
- 不做 macOS CUDA 推理。
- 不把模型权重打包进安装包。
- 不把 GBC/Trainer 的 Python 运行时塞进 Electron。
- 不为旧 `project.json` 保留兼容层。

## 9. 验收原则

- UI 路径存在 ≠ 已验收。
- 真实 NVIDIA/Windows/Linux、安装包、远端 host 必须以实机结果更新 [status.md](status.md)。
- 旧文档/截图只作历史。
