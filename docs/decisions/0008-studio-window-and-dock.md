# ADR-0008：单 Studio 窗口、工作台覆盖层与可停靠面板


## 背景

MossStudio 已经有创作、终端、设备、引擎、模型、训练等多个入口。独立窗口越多，用户越容易在多窗口之间丢失上下文；同时创作页本身被固定侧栏和项目管理器切碎，画布占比不足。

## 决策

1. **只保留两个 BrowserWindow**：`studio` 与 `trainer`。`studio` 使用较大的普通窗口（1600×1000 起始，不调用 OS 全屏）；`trainer` 仍单独保留。
2. **launcher / devices / terminal 不再是窗口**。设置、引擎、模型与下载、设备、训练、画廊、诊断改成底部平铺页面 tabs；创作是默认页；终端变为 Studio 底部抽屉。
3. **创作页为三列**：左侧生成参数面板，中间画布与生成工具条，右侧图层/布局/Agent 面板（Agent 默认停靠右栏）。
4. **面板可停靠、可调整**：包括 Agent 在内的面板头部可拖到左槽、右槽或画布悬浮层；左/右栏可在画布边缘拖拽宽度，也可收起为窄轨并用展开按钮恢复；卡片底边可纵向拖拽，浮动卡片可拖角调整尺寸；停靠/尺寸关系暂不持久化。
5. **项目管理器移除**：画布 tabs 只放在中间画布列上方；左/右工具面板从顶部开始吸顶。tabs 可横向滚动、可拖动排序；`+ 新建画布` 在 tabs 右侧，tab 显示名称和保存状态。全局页面切换放在底部平铺 tab（创作/引擎/模型/设备/训练/画廊/诊断/设置）。
6. **画布交互**：滚轮以鼠标焦点缩放；`手型` 工具或鼠标中键拖动平移；工具条提供 100% 重置/缩放按钮；`画框/选择` 继续负责区域编辑。
7. **兼容入口映射**：旧的 `openWindow('launcher'|'creator'|'terminal'|'devices')` 调用被映射为 Studio 内的管理/抽屉意图，不再创建新窗口。

## 后果

- 启动即进入创作，管理面不再抢占主流程。
- Studio 的窗口状态更简单；Agent 已作为普通可停靠面板，默认进入右栏，可拖出为浮动卡片。
- 面板允许用户按工作流分配空间，但布局状态目前仍在运行时内。
- 未保存画布会以稳定 snapshot tab 保留，打开已保存 Project 不会丢失未保存草稿；多草稿仍未支持。
- 面板停靠关系与 tab 顺序暂不跨重启持久化。
- 管理页仍复用原页面组件，路由仍走同一 HashRouter；不再是左栏覆盖层。
- 全局页面 tab 常驻底部，终端抽屉在其上方打开。
- 训练 UI 保留独立窗口，因此“两个窗口”是 Studio + Trainer，不含系统级弹窗/模态。

## 验证

- `--scenario=windows` 只创建 Studio 和 Trainer。
- `pnpm typecheck`、`pnpm build`、`--smoke`、`pnpm test:ui` 通过。
- `--screenshot` 生成 Studio/管理页/Trainer 截图。
